# Fix: Class/school tag links return 404

## Problem
Clicking a class in the nav (e.g. "Cleric") returns a 404.

Two stacked causes:

1. **The tag-page generator never runs.** Tag pages are generated by the custom
   plugin `_plugins/tag_gen.rb`. The site builds through the `github-pages` gem
   (see `Gemfile`), which forces Jekyll safe mode and points `plugins_dir` at a
   throwaway directory — custom `_plugins/` are silently disabled. So no
   `tags/*.html` pages exist in the built site at all.
2. **URL mismatch.** Even if the plugin ran, `_includes/header.html` links to
   `/tag/<class>` (singular, no extension) while the plugin writes
   `tags/<tag>.html` and `_layouts/post.html` links to `/tags/<tag>.html`.

## Fix (minimal, no dependency changes)
The set of tags worth a landing page is small and fixed (8 classes + 8 schools,
already enumerated in `_data/classes.yml` / `_data/schools.yml`), so generate
them as **static pages** instead of via a plugin:

- Add `tags/<tag>.html` source pages, 4 lines of front matter each, using the
  existing `tag_index` layout:

  ```yaml
  ---
  layout: tag_index
  tag: cleric
  title: Cleric
  ---
  ```

- Point `header.html` at `/tags/<tag>.html` (matches the links `post.html`
  already emits, so spell-page tag links start working too).
- Delete `_plugins/tag_gen.rb` — dead code in CI, and it would collide with the
  static pages when building with plain Jekyll locally.

Level tags (`cantrip`, `levelN`) keep linking to homepage anchors, unchanged.

## Trade-off
Adding a new class/school means adding one 4-line file under `tags/` alongside
the `_data` entry. Acceptable for a fixed 5e taxonomy; avoids swapping the
whole `github-pages` dependency stack for a plugin that generates 16 pages.
